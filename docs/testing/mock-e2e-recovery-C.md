## Route contract and impact

The capability-center gallery remains `/workspace/capabilities/agents`; `/workspace/agents` is its compatibility redirect, documented in `frontend/src/app/workspace/agents/page.tsx`. The active create and detail routes are `frontend/src/app/workspace/agents/new/page.tsx` and `frontend/src/app/workspace/agents/[agent_name]/page.tsx`. The old `/workspace/capabilities/experts/*` pages redirect to those live routes. Gallery links now target `/workspace/agents/new` and `/workspace/agents/<resourceIdentity>`. The Resource Governance acceptance matrix requires UUID dynamic routes while displaying slug/display name; detail page `router.replace` canonicalizes an alias/slug route to the resource UUID. Case #4 therefore checks that same canonical resource ID after publishing while its new chat URL and run payload keep `agent_name=test-agent`.

C3 uses the official `GET /api/resources/{resource_id}/published` seam; `backend/app/gateway/routers/resources.py:get_published_resource` applies `ResourceService.get_visible` before returning published content. The list response remains metadata-only and unmodified. On AgentCard, available published detail supplies only badge fields; if no published Agent value is available, badge rendering falls back to the list Agent. The rest of the card remains sourced from the list entry.
