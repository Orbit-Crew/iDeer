## 02→恢复的转向：从顺序依赖到逐项分类

首批的 T2/T3 假设 Mock 失败源于顺序依赖，但目标用例单跑即失败，且 55 项中没有一项满足"单跑五过 + 指定前序后五败"的因果判据。恢复批没有强行维护这个假设，而是把 55 项按生产基线逐项取证、分组、建立修复票。回头看，这个转向是正确的：根因主题几乎全部是过期测试契约与真实产品缺陷，而不是测试间污染。

按组的根因主题（详见 mock-e2e-recovery-{A..F}.md 与诊断表）：

- 过期契约/过期定位器（占大多数）：A 组 14 项几乎全是迁移前路由、`能力中心` 标题、`?tab=plugins` 深链与过期 settings key；B 组 #27–30 的模型触发器可访问名过期；C 组 #50–51 的 "New Expert"→"New Agent" 与过期 create href；E 组 #7/#8/#52 的自动开面板与 "Code"→"View source" 过期预期；F 组 #38 断言已被批准体验移除的静态建议行。
- 真实产品缺陷（少量、独立子票、最小修复）：A1 移动端资源画廊缺 sidebar 触发器；E1 保存冲突状态在 1280×720 下零宽不可见（shrink-0）；D 组 #44–45 归档聊天头缺恢复控件（ThreadArchiveStatus 挂载）；B 组 #35/#36 自动 fallback 覆写账户偏好（产品行为修复，附 DOM/store 回归）。
- 测试自身竞态/夹具缺口：C 组 #2 fill-before-hydration、#54/#55 `networkidle` 不可靠与 CodeMirror fill 追加；D 组 #15–19 的夹具身份/请求建模缺口；B 组 #37 SSR 身份 409 假设；F 组 #1 一次性 `boundingBox()` 几何采样竞态。

## 环境与沙箱处理

- 恢复批延续了"受限环境记录阻断、允许环境原样重跑、不改代码绕过"的约定。本会话内所有浏览器/socket 命令直接在允许环境执行，lane 预检全部 ready，没有出现环境阻断项。
- 生产服务器由 root 持有并跨票复用（端口 3001、auth-disabled、BUILD_ID 逐票核对）。这避免了每票重建构建的成本，但 A 组历史命令写 3000、恢复批统一改指 3001 的细节必须在验收记录中显式说明，否则候选与服务绑定会出现歧义。
- 8001 Gateway 有意离线，代理 `ECONNREFUSED` 日线是预期噪音；本批继续只登记、不归因。

## 残余风险与未决项

- **pr-standard 红灯（本批最直接的后续工作）**：03-D 的产品改动（ChatPage 读取 `t.projects.projectUnavailable`、Chat/AgentChat 页头挂载依赖 react-query 的 `ThreadArchiveStatus`）与 3 个未同步更新的页面单测文件冲突，93 项 Vitest 失败。E2E 层有完整 Provider 树所以全绿，恰恰说明这类"新增依赖挂载"只能在单元层被抓到——而本批实施时只跑了聚焦与 Mock 验收，没有跑页面单测所属的 frontend-standard。教训：改动 `app/` 路由页（新增 hook 挂载、读取新翻译命名空间）时，页面单测是最窄的受影响静态检查，应与聚焦 E2E 一起跑。
- **#39 / #47 未确认根因**：两组用例在当前候选反复通过（含五次重复与全量），历史失败无法在相同模式下复现。按约定不写因果结论；若未来复现，诊断入口应保存服务模式、worker/retry、实际顺序与请求证据后再下结论。
- **顺序依赖假设未证伪也未证实**：T2 只能结论"未取得复现"。Mock 夹具/注册/清理层面是否真的不存在跨用例污染，本批证据不足以做全局断言；下一次全量若出现新的孤立失败，应优先按"单跑 vs 前序"判据重新检验。
- **inventory 与 lane 计数的口径差**：清单对 frontend-mock-e2e 文件集计 487 节点，正式 lane 自身收集 413。清单是静态/框架发现，lane 收集才是通道权威计数；记录两者时应并注口径，避免误读为丢了 74 个测试。

## 对下一批的建议

1. 开一张最小对齐票：为 3 个页面单测文件补 QueryClientProvider 包装与 `projects.projectUnavailable` 翻译 mock（或等价最小调整），重跑 frontend-standard 子 lane 与父 pr-standard，然后本批才能改判 complete。不借此扩大范围。
2. 把"修改 `app/` 路由页时必须同时跑该页面的单测文件"写入 agent 实施检查清单；这是本轮唯一造成的红灯，且完全可以在 D 组实施期内以秒级检查发现。
3. 保留 03 为 blocked 直至出现满足判据的顺序依赖复现；不要用"全量通过"反推顺序依赖不存在。
4. 延续"根因主题分组 + 逐项断言映射"的记录方式：本批 55 项的修复-断言对应关系在复审与本次验收中均可直接引用，是有效投入。
