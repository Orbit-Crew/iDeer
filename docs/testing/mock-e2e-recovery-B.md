## Changes

- All three preference fixtures record method, `X-Expected-User-Id`, response status, and PATCH body. They do not record authorization headers. SSR `e2e-user` reads return 409; only the expected browser owner can read/write.
- Model trigger tests use the stable `model-selector-trigger` test id, then separately assert its visible selected-model text. Favorite, unavailable-model, account/thread ownership, and explicit preference assertions remain active.
- The normal and custom-agent App Router callbacks pass the automatic option to `resolveThreadContext`; explicit user actions continue through `setSettings("context", context)`.
- `resolveThreadContext` now initializes existing local settings before handling a cold automatic fallback, persists device settings as before, updates an already-existing explicit thread override, and does not create a new fallback override. It does not enqueue an account preference edit while preferences are inactive.
- Added regressions to the preferences DOM test and settings-store test for delayed account hydration, no fallback override, and preservation of cold local settings.

The `resolveThreadContext` GitNexus impact was **HIGH** after the two route call sites were connected: four direct dependents, three processes (`AgentChatPage`, both `ChatPage` entry points), and the Workspace module. The affected calls resolve models/modes automatically. Existing explicit selection paths remain unchanged. Normal and custom-agent route source hashes matched `.gitnexus/gitnexus.json`; the final index had no incomplete reasons. The worktree index status is stale relative to the uncommitted candidate, as expected, while the indexed hashes for the touched symbols/tests match their source.
